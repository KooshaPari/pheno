# Open Knowledge Format (OKF)

OKF is the machine-readable index layer for Phenotype genesis documentation. It enables LLM wikis, cross-repo search, agent context injection, and embedding pipelines without duplicating prose in multiple stores.

**AgilePlus trace:** FR-GENESIS-002 (machine-readable doc index per repo)

## Design goals

1. **Single manifest** — one YAML file lists all governance artifacts and dimensional SOTA paths.
2. **Stable IDs** — every chunk and artifact has an `okf_id` that never gets reused.
3. **Relative links** — chunks and manifests use repo-relative paths so RAG relocation does not break retrieval.
4. **Provenance** — intent prompt scrape metadata is first-class in the manifest.
5. **LLM-friendly** — summaries, injection order, and embedding hints are explicit fields, not conventions buried in READMEs.

## File layout

```
okf/
  manifest.okf.yaml    # canonical index (required)
  wiki/
    README.md          # human navigation + chunk index table
    chunks/            # optional pre-chunked embeds (generated or hand-maintained)
      *.okf.md
```

Bootstrap example: [`templates/genesis/okf/manifest.okf.yaml`](../../templates/genesis/okf/manifest.okf.yaml)

## Manifest schema (v1)

### Top-level fields

| Field | Required | Description |
|-------|----------|-------------|
| `okf_version` | yes | Schema version string, e.g. `"1.0"` |
| `project` | yes | Identity block (see below) |
| `artifacts` | yes | List of indexed markdown/yaml governance files |
| `dimensions` | yes | Map of SOTA dimension name → path |
| `provenance` | yes | Intent prompt scrape metadata |
| `llm_wiki` | yes | Chunking and injection hints |

### `project` block

```yaml
project:
  id: "koosha.phenotype.<repo-slug>"   # stable fleet ID
  name: "<Repo Display Name>"
  charter_ref: "charter.md"
  review_ref: "review.md"
  boundary_class: genesis | sdk-domain | application | tooling | personal-protected
  agileplus_spec: null                  # e.g. "AgilePlus/kitty-specs/024-foo" if tracked
```

### `artifacts` entries

Each entry describes one governance file:

```yaml
artifacts:
  - id: intent-root              # stable okf artifact id
    path: intent.md
    kind: intent                 # intent | governance | review | sota | adr
    version: "1.0.0"             # optional doc version
    summary: "<≤240 char summary for tool descriptions>"
    links:
      - docs/intent/synthesis.md
    tags: [genesis, user-goals]
  - id: charter
    path: charter.md
    kind: governance
    summary: "Scope and decision rights for {{PROJECT_NAME}}"
  - id: review-kilo
    path: review.md
    kind: review
    standard: kilo-code-stand@1
    summary: "Automated PR review contract for agents"
  - id: sota-root
    path: SOTA.md
    kind: sota
    summary: "Executive state-of-the-art summary"
    dimensions: [technical, dx, ux, ax, security, ops, cost]
```

### `dimensions` block

Maps dimension keys to markdown paths (must exist or be marked N/A in SOTA root):

```yaml
dimensions:
  technical: docs/sota/technical.md
  dx: docs/sota/dx.md
  ux: docs/sota/ux.md
  ax: docs/sota/ax.md
  security: docs/sota/security.md
  ops: docs/sota/ops.md
  cost: docs/sota/cost.md
  alternatives: docs/sota/alternatives.md
  fork: docs/sota/fork-rationale.md
```

### `provenance` block

```yaml
provenance:
  intent_prompts: docs/intent/prompts/
  last_scrape: "2026-06-16T00:00:00Z"   # ISO-8601 or null before first scrape
  sources:
    - cursor
    - forge
    - claude
    - codex
  scraper_version: "extract-intent-prompts@1"
```

### `llm_wiki` block

```yaml
llm_wiki:
  chunk_max_tokens: 800
  cross_link_style: relative
  embedding_hint: "title + summary + first_h2"
  injection_order:
    - charter.md
    - review.md
    - intent.md
    - SOTA.md
  exclude_paths:
    - docs/intent/prompts/**   # verbatim prompts: link, do not embed whole corpus by default
```

## Chunk file format (`*.okf.md`)

Each chunk is standard Markdown with OKF YAML frontmatter. Chunks may live under `okf/wiki/chunks/` or be generated by tooling.

```markdown
---
okf_id: sota-dx-001
okf_version: "1.0"
parent: docs/sota/dx.md
heading: "Local dev loop"
tags: [dx, cli, forge]
summary: "How developers bootstrap a repo from genesis templates"
supersedes: null
deprecated: false
embedding_hint: "title + summary + first_h2"
---

Prose body for this chunk. Use relative links only: [charter.md](../../charter.md).
```

### Chunking rules

1. Split on `##` headings; keep each chunk under `chunk_max_tokens`.
2. Include `summary` in frontmatter even when body repeats the first paragraph — embedders read frontmatter first.
3. Cross-reference sibling chunks with `okf_id:` links in prose: `See okf_id:sota-dx-002`.
4. Do not chunk verbatim prompt files by default — link from synthesis chunks instead (privacy + noise).

## LLM wiki adaptations

| Adaptation | Rationale |
|------------|-----------|
| Stable `okf_id` | Deprecate with `supersedes:`; never reuse IDs across rewrites |
| Relative links only | Chunks relocate without breaking RAG retrieval |
| ≤240 char `summary` | Fits tool descriptions and embedding metadata |
| `verbatim_hash` on prompts | Detect drift if prompt file edited after scrape |
| Injection order in manifest | Agents load charter before intent before SOTA |
| Dimension map | Review agents fetch only relevant SOTA slice for dependency changes |

## Agent injection order

When building a context window from OKF:

1. Load `manifest.okf.yaml` — resolve paths and summaries.
2. Inject `injection_order` files in sequence (truncate at token budget using summaries first).
3. For PRs touching dependencies, add artifact from `dimensions.security` and `dimensions.alternatives`.
4. For scope questions, prefer `charter` artifact over README.

## Validation

```bash
# Planned CLI
hexakit okf validate okf/manifest.okf.yaml
hexakit okf chunk --manifest okf/manifest.okf.yaml --out okf/wiki/chunks/
```

Checks (planned):

- All `artifacts[].path` and `dimensions.*` paths exist
- `charter_ref` and `review_ref` match manifest `project` block
- No duplicate `okf_id` in chunks
- Summaries within length limit
- `review-kilo` artifact declares `standard: kilo-code-stand@1`
